Why this matters

No encryption in transit

HTTP sends all data as plain text. Anyone on the same network (cafe Wi-Fi, hotel, corporate proxy) can read your username, password, and everything you submit.

No identity verification

HTTPS certificates prove the server is who it claims to be. HTTP has no certificate — the "bank" site you're talking to could be anyone.

Attackers intercept easily

On HTTP, a man-in-the-middle can silently modify page content — injecting fake forms, malware, or changing where your form submits.

What to do

If a site shows "Not Secure" — especially on a login or payment page — do not enter any credentials. Check the URL: legitimate services always use https://

Training Demo — Insecure Website (HTTP)

This page simulates what an HTTP-only (insecure) website looks like in your browser. Key takeaways:

  • "Not Secure" appears in Chrome/Edge/Firefox address bar for all HTTP sites
  • Padlock icon absent — HTTPS sites show a padlock (or just the domain in newer browsers)
  • Never login on HTTP — credentials travel unencrypted across every network hop
  • HTTP ≠ fake — some real sites use HTTP, but none should ask for passwords
